# Codex consumer integration

The V3 owner accepts the bounded deterministic consumer scope. This is a new
provider route, not a replacement for accepted Claude evidence. Runtime admission
belongs to Experiment; acquisition and immutable decisions belong to Client;
qualification and independent archive validation belong to Journal.

## Design before implementation

Use the existing one-shot async Client and original StartedExecution through
Experiment. Retain the original response before qualification, the actual
termination receipt, original decision and capture, including failure paths.
Select the explicit Codex terminal profile and reject foreign execution or
archive identities. Never reconstruct a successful response or decision.

The pinned PetClinic before-tree, simple prompt, baseline/final independent
measurement, edit-surface/build/coverage Jury, detached reader and nine ACT
outputs remain required. The existing Claude route and its immutable accepted
archive stay unchanged. A local executable fixture exercises wiring only.

Codex native launch remains closed. The existing product policy permits writes
only under src/test and exactly the foreground Maven build command. Workspace
write sandbox alone does not enforce those requirements. The final proposal must
state actual writable roots, operation limits, process cleanup and wall-time
controls; unknown cost and unsupported token/internal-turn ceilings remain explicit.
No synthetic policy observation qualifies native write/edit behavior.

## Verification boundary

Use an isolated Maven cache with exact producer hashes. Run the complete offline
Java verification and checked-in Python tests, then actual packaged-consumer and
separate reader checks. Failed result and archive mismatch controls must preserve
truthful original evidence. A native prelaunch proposal is not launch authority.
